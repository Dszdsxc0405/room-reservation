# 跨模块接口 V1

> 2026-11-06。以下确定接口责任、触发时点和结果；具体 URL、字段名及错误码在开发前按本契约细化。数据归属见[六人分工](12_六人分工与数据归属_V1.md)，业务结果见对应 BP/AC。

| D → M1/M2 | 保存关闭教室、缩短开放时间或注销座位时，分别处理个人预约、整室批准及待审申请；单座位注销保留整室安排并提示不可用座位 | AC-12/36 |
| M1/M2/M3 → D | 业务服务决定通知对象与内容，D 投递站内消息并记录结果；D 保存操作审计 | AC-09/12/18/21 |
| D → M1 | 管理查看读取个人预约、签到及违约事实；D 按授权范围展示详情并汇总预约量、取消数、签到量、违约量及签到率 | AC-14 |

## 共同约定

1. 写入请求携带唯一操作编号、来源模块与来源 ID、资源 ID、受影响时段、原因和发起人。提供方按操作编号去重，重复请求返回同一处理结果；调用超时先查询结果再重试。
2. 发起方先记录“处理中”，再调用依赖接口。M2 终审、M3 报修和 D 管理计划在相关模块确认后才标记最终成功；失败保留待处理记录并重试，不能显示已经完全生效。M1 对限制与个人预约的处理在本模块事务内完成。若终审最终失败，M2 须解除已写入的本申请限制；尚未完成的报修或管理计划须继续补齐跨模块处置或撤销自身待生效变更。
3. 所有服务只修改本模块拥有的数据。M1 在同一教室的预约和限制写入之间做并发保护；存在报修或管理关闭限制时拒绝新整室占用。M2 终审前重验其他整室批准、D 开放配置及 M3 报修状态，并在最终确认时检查申请尚未被撤销。M3 报修提交前确认资源无未结束工单；维修中仍按 V1 等待正在使用的安排结束。
4. 通知在业务结果确认后投递；投递失败保留记录重试。解除限制只按来源删除，不自动恢复此前取消的预约或申请。

开发前把本表细化为请求/响应样例、权限校验、错误码及重试上限，并至少联调：并发抢座、整室终审与新约、报修与新约、管理变更与在途申请、重复请求及网络超时。
