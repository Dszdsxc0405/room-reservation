## 公共层 D 的承担方案

**当前方案：**六人均为全栈工程师；A/B 负责 M1，C 负责 M2，成员代号 D 负责 M3，E/F 负责公共层 D。公共层主责主数据、配置和权限、消息、审计与运营统计。具体职责与数据修改边界以[分工文件](12_六人分工与数据归属_V1.md)为准。

**评估依据：**课程要求比较工作量、契约治理和故障责任归属。独立安排 E/F 可给公共能力明确维护者；M1/M2/M3 通过 D 的公开接口取数。另一种可讨论的方案是让业务模块兼任 D，或将公共能力分给多个模块；两种方案对人员负载、接口责任和故障定位的影响，仍须由实际六名成员复核。

**确认状态：**需求负责人已认可当前分工；实际成员尚未认领 A～F，组内讨论、备选方案比较及一致意见尚未记录。因此本项尚不能称为“六人已达成一致”。开工时补记参与者、日期、各方案评价和最终结论；若改变分工，同步更新分工文件、接口归属和[计划](plan.md)。

## 环境隔离

**环境隔离（2026-11-11 确认）：**比较“开发测试合用”与“三套隔离”，采用后者，因为课程分别要求开发、测试、生产环境，也便于避免测试数据影响开发或演示。三套环境可先在当前电脑运行，各用独立数据库；同机资源负载和 PostgreSQL 实例数量待核实。实施见[技术方案](13_技术方案_V1.md)和[运行文档](operations.md)。
