# 需求分析完成后的步骤

> 当前停在设计文档完成：业务需求基线 V1、六人分工、技术方案和跨模块接口均已记录。以下工作尚未执行。

1. **开工准备**：六名实际成员认领 A～F；建立私有 GitHub 仓库并推送本地历史；约定分支、评审和共享数据变更规则。
2. **环境与流水线**：在当前电脑核实 Docker、数据库和资源条件；分别建立隔离的测试、演示环境。在私有仓库配置提交/合并请求自动构建测试、失败阻断；当前电脑部署用 Runner 在线时自动更新测试环境，演示环境按版本标签人工触发发布并演练回退。
3. **接口细化**：按[跨模块接口 V1](14_跨模块接口_V1.md)补齐请求/响应样例、权限、错误码、超时与重试上限。四个服务先用真实 HTTP 调用完成最小联通；各模块只迁移自己的数据库结构。
4. **并行开发**：A/B 做 M1，C 做 M2，D 做 M3，E/F 做公共层 D；按 BP 的 AC 实现页面、业务和必要测试。共享接口或数据库变更先交叉评审。
5. **整体联调与验收**：重点跑并发预约、签到超时、整室审批占座、报修提交下架、管理计划取消安排、来源解除、消息失败重试；从空库重放迁移并用实际网络调用验证。对照 AC 人工验收，记录未通过项和修复结果。
6. **交付**：完成演示环境发布与回退演练，保存版本标签、构建测试、迁移、联调及人工验收记录。

技术参数与容量以环境核实和测试结果为准；若业务结果要变，先由需求负责人决定，再更新决策记录、受影响 BP/AC 和基线版本。
