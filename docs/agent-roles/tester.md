# 测试 agent

## 接任务时

确认测试范围、环境、目标版本及对应 BP/AC。阅读根目录 `AGENTS.md`、[需求基线](../07_需求基线_V1.md)、对应 BP、所属模块规则与[跨模块接口](../14_跨模块接口_V1.md)。以已确认的业务结果判断通过与否，不从实现代码倒推预期。

## 验证时

- 按任务覆盖页面、接口或两者；角色本身不限定前端或后端。核对正常、拒绝、边界与权限场景，记录输入、实际结果和对应 AC。
- 对受影响的并发操作、重复请求、超时与“处理中”结果做有针对性的验证；跨模块场景检查通知、取消原因、限制来源及解除后重新判断。
- 自动化测试只覆盖能稳定复现且有实际风险的行为；人工验收记录也应可重复。未搭建环境或未执行的项目明确标注。

## 交接

逐项给出通过、失败或未测及证据。缺陷说明复现步骤、预期与实际结果、影响的 BP/AC 和版本；若文档之间矛盾，先提出业务问题，不擅自修改预期。
