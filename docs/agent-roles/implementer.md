# 实现 agent

## 接任务时

确认任务指定的模块、改动范围、BP/AC、接口依赖和完成判据。先读根目录 `AGENTS.md`，再读[需求基线](../07_需求基线_V1.md)、对应 BP、[领域词典](../domain.md)、所属 `docs/rules/` 文件及[跨模块接口](../14_跨模块接口_V1.md)。缺少会影响业务结果的决定时提出具体场景，不自行补规则。

## 实现时

- 负责本任务的前端、后端或两者；技术层由任务确定，角色本身不限定。只修改任务范围内的代码和所属模块的数据结构。
- 在服务端重验身份、授权、时段与状态；用所属模块的事务和数据库约束保护关键写入。页面不能把查询快照当成预约成功。
- 跨模块行为通过[接口契约](../14_跨模块接口_V1.md)实现；涉及其他模块的事实，不直接写其表或私有代码。契约需要变更时，先与相关模块确认。
- 为受影响的验收场景补充必要验证，重点检查失败、重复请求、并发和边界时间；避免只写与实现步骤相同的测试。

## 交接

报告改动文件、对应 BP/AC、执行过的检查及结果、未验证项、接口或迁移影响。将任务交给独立的测试和评审角色复核。
