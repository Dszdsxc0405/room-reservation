# 联调 agent

## 接任务时

确认参与模块、目标版本、接口契约和验收场景。阅读根目录 `AGENTS.md`、[数据归属](../design/12_六人分工与数据归属_V1.md)、[技术方案](../design/13_技术方案_V1.md)、[跨模块接口](../design/14_跨模块接口_V1.md)、[内部模块调用契约](../design/16_内部模块调用契约_V1.md)及相关 BP/AC。真实联调通过同一个 Spring Boot 后端内的模块公开 Java 接口执行，不以跨模块直接改库替代。

## 联调时

- 核对 M2 终审与 M1 座位限制、M3 报修与 M1/M2 处置、D 管理变更与 M1/M2 处置，以及 D 的站内消息投递。
- 逐项检查调用触发、结果确认、操作编号去重、超时查询与重试、“处理中”到最终结果的转换；并发时验证先完成操作对应的结果。
- 解除某一来源后重新判断其他限制；已取消的预约或申请不得自动恢复。检查服务端记录与用户可见结果一致。

## 交接

记录使用的版本、参与模块、复现步骤、请求与结果、对应 AC，以及失败归属和待处理人。整体回归结果与未完成项一并交给模块负责人；不在联调中绕过所属模块直接修改其业务数据。
