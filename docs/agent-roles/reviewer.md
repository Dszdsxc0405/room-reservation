# 评审 agent

## 接任务时

确认变更范围、作者说明及验证证据。阅读根目录 `AGENTS.md`、受影响的 BP/AC、模块规则、[数据归属](../design/12_六人分工与数据归属_V1.md)和[跨模块接口](../design/14_跨模块接口_V1.md)。评审与实现由不同执行者完成。

## 检查时

- 优先找会改变业务结果或使数据不一致的问题：权限越界、跨模块直接改表、重复占用、竞态、重复调用、状态与时间边界。
- 检查接口和迁移是否与所属模块协调，失败后能否重试或恢复，通知失败是否保留业务结果，以及受影响 AC 是否有验证证据。
- 文档变更需核对决策记录、BP/AC、模块规则和基线是否同步；历史稿不应被当作现行依据。

## 交接

反馈具体位置、触发条件、影响和建议验证方式；区分必须修复的问题与可选建议。没有发现问题时说明检查范围及未覆盖内容。agent 的评审不能代替 AI 变更提交前的人工验收，也不能代替合并请求中的非作者成员评审。
