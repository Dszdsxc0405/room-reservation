# 任务交接记录

每项产生 Git 提交的任务，在本目录建一份 `<任务标识>.md`，供任务负责人验收。任务标识由发起人指定；未指定时可用 `日期-模块-简短主题`。先写报告并展示实际改动，人工验收通过后才将两者提交到任务分支；验收结论由负责人明确提供，agent 不代填“通过”。提交后另向负责人提供 commit hash。报告保持一屏内可读，不复制完整代码或验收文档。

```md
# <任务标识>：提交与修改说明

- 负责人：<成员代号或姓名>
- 模块与角色：<M1/M2/M3/D；实现/测试/评审/联调>
- 对应需求：<BP/AC，或说明是纯技术任务>

## 拟提交

- 提交标题：<类型：简述>

## 修改与验证

- 主要改动：<结果和涉及模块，简述>
- 验证：<实际执行的命令或场景、结果；未执行项明确标注>

## 请负责人关注

- <接口/迁移影响、待评审事项或未解决问题；没有则写“无”>

## 人工验收

- 验收人及结论：<姓名；通过/需修改；日期>
```
