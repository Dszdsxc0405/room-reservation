## 1. BP 边界与主线

**触发**：学生希望在某个时段使用一处自习座位。**结束**：产生可追溯的有效个人预约，或得到明确的无法预约结果。签到、提醒和违约处置属于 BP-02；历史记录中的“再订”是本流程的另一入口。

主线：学生选择日期、整点时段与座位条件 → 系统查询其可用范围内的座位 → 学生选座并提交 → 系统在提交时重新校验时段、资格和可约性 → 预约生效并显示结果。任务书支持预约、搜索和历史再订；“查询后提交时重验”最初是防止旧查询结果造成重复占用的**分析推断**，现已随 AC-06 获用户认可，仍待实现与验收。

| 分支/情形 | 业务结果 | 为什么要检查 |
|---|---|---|
| 无符合条件的座位 | 查询无结果；不产生预约 | 查询不保证成功 |
| 院系自习室、整点、不可跨日与最长时长限制 | 不符合者不得成功预约；提示形式待定 | R-01/R-02；时段精度与跨日决定 |
| 座位已有有效个人预约 | 重叠时段最多一笔生效（R-13）；另一个提交不成功 | 同一资源时间冲突 |
| 待审整教室申请 | 不占用座位（R-15）；最终批准时自动取消冲突的未来个人预约并通知（Q-01） | 申请与审批结果不同 |
| 已批准整教室占用、报修或维修限制 | 已知限制不得被个人预约绕过；组合解除遵循 R-17 | R-03/R-04/R-05；Q-25 |
| 从本人历史记录选原座位 | 作为入口，仍按当前条件判断新时段；学生只能查看本人历史 | 历史不是新预约的有效凭据 |
| 查询之后规则或占用改变 | 提交时结果可能失败 | 读取与写入之间的竞态 |
| 已预约后整室获批或报修 | 整室获批或教室/座位报修提交时，取消影响范围内冲突的未来个人预约并发站内消息，不记违约；报修时已开始但尚未签到且尚未构成超时的预约立即按报修取消。若此前已构成超时未签到但任务延迟，先补做超时违约，再处理报修。已签到正在使用的预约可用到结束（Q-01/02/15/25；2026-11-20 延迟处置决定） | BP-01 与其他 BP 的先后顺序 |
| 整室批准后来被取消 | 此前因获批而取消的个人预约不自动恢复；学生可按现行规则重新预约 | 取消与重新预约是不同操作 |
| 已预约后管理员计划关闭、缩短开放时段或注销座位 | Q-04/17：保存计划或注销座位时立即取消冲突的未来预约并通知；立即生效时，已签到正在使用的预约可用到原定结束，已开始但未签到的预约保留原签到窗口、允许签到，逾期未签到照常记违约；Q-15：由管理变更取消的未来预约不记未签到违约 | BP-03/05 的管理变更 |
| 学生主动取消有效预约 | 不纳入本次交付（Q-31） | 任务书未规定，用户已决定“不需要” |

## 2. 对象、事件与约束

| 业务对象/事实 | BP-01 读取或改变什么 | 相关事件 |
|---|---|---|
| 学生与资格 | 身份、院系、可用范围；重叠时段不得同时持有不同座位预约（R-14） | 发起查询、提交 |
| 自习室和座位 | 所属、唯一编号、开放时段、插座标记、管理可用性 | 管理员维护（BP-03） |
| 有效个人预约 | 学生、座位、时间区间、生效/取消事实与来源 | 提交生效（BP-01）；签到/超时释放（BP-02） |
| 整教室时段限制 | 已批准的教室与时间区间；待审批不占座（R-15） | 审批/驳回/撤销（BP-06） |
| 报修/维修限制 | 已提交未结束的教室或座位工单；验收或维修前撤单后解除本工单影响 | 报修提交、验收、撤单（BP-07） |
| 配置/权限 | 预约上限、开放和角色权限的现行值 | 参数/权限改变（BP-05）；旧预约保留见 Q-05 |

**已确认的业务不变量**：同一座位重叠时段最多一笔有效个人预约（R-13）；同一学生不得持有重叠时段的不同座位预约（R-14）；解除某个来源的限制不清除其他仍有效的限制（R-17）。详见[决策记录](08_业务决策记录_V1.md)。实现与验收尚未发生。

## 3. 规则与 Q：不把推断写成任务书事实

| 已有任务书依据 | BP-01 的可观察含义 | 仍未说明的部分 |

| R-04：教室维修中全室下架，座位维修中仅该座位下架；验收后解除本来源 | 用户另决定报修提交时即限制新约并取消受影响的未来预约；其他座位按自身条件可约 | Q-02/25；组合解除（R-17） |

| R-06：未签到取消并释放 | BP-02 后应重新评价是否可约 | 截止时点及余下整点时段已由 Q-09 决定（R-18） |

本 BP 受 BP-02/03/05/06/07 的签到、资源、配置、整室审批和报修结果影响，相关 Q 见各 BP 正文及决策记录。Q-29 按学校本地自然日起算：每天 00:00:00 开放第 3 天整天；例如周四 00:00:00 可约周日，周五 00:00:00 可约周一。

**用户决定的规则索引**：R-13 同座位重叠时段至多一笔有效个人预约；R-14 同一学生不得持有重叠时段的不同座位预约；R-15 待审批整室申请不占座；R-16 最多提前 3 天、已开始时段不可预约，按学校本地自然日每天 00:00:00 开放第 3 天整天（Q-29）；R-17 解除一项来源后若其他限制仍有效或开放条件不满足，则仍不可约。它们来自用户决定，不属于任务书原文。

## 4. CAP、UC 与 US

| CAP（能力，未定所有者） | UC（参与者目标） | US（小块业务价值） | 对架构的依赖 |
|---|---|---|---|
| CAP-01 按资格/时段/座位属性查询当前可约性 | UC-01 学生查找座位 | US-01 查询合适座位 | 空间主数据与限制来源的读取契约 |
| CAP-02 校验并创建有效个人预约，记录来源 | UC-02 学生预约选定座位 | US-02 成功预约或得到明确拒绝 | M1 负责最终校验、写入及并发保护，见[技术方案](13_技术方案_V1.md) |
| CAP-03 通过历史记录进入新的预约 | UC-03 学生再次预约原座位 | US-03 从历史记录发起新预约 | 历史读取与 CAP-01/02 的复用 |

CAP 不等于模块，UC 不等于页面，US 不等于数据库任务。US-03 可复用原座位的识别信息，但不能跳过新时段校验。
