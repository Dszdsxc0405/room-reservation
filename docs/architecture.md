# 系统架构与模块边界

> 本页是架构入口。技术选择依据在[技术方案](13_技术方案_V1.md)，数据主责在[六人分工与数据归属](12_六人分工与数据归属_V1.md)，调用时点和结果在[跨模块接口](14_跨模块接口_V1.md)；本页不复制它们的细节。当前是设计方案，尚无已部署系统。

一个 Vue Web 应用面向学生、教职工和管理员；M1、M2、M3、公共层 D 是四个独立 HTTP 服务。开发、测试、生产三套环境逻辑隔离，各用独立 PostgreSQL 数据库；每套环境内模块共库，但各自修改所属业务事实。用户 RBAC 与模块数据主责分别约束用户操作和服务写入。

| 模块 | 事实主责 | 对外协作要点 |
|---|---|---|
| M1 | 座位预约、签到、违约、时段限制、最终可约性 | 接受 M2、M3、D 的来源限制请求；其他模块不能直接改预约 |
| M2 | 整室申请与审批 | 终审通过后请 M1 限制座位；教室报修或管理计划会影响申请 |
| M3 | 教室/座位报修与维修 | 提交报修时请 M1 限制座位；教室报修另请 M2 处置整室申请 |
| D | 主数据、配置、RBAC、站内消息、审计与运营统计 | 向业务模块提供权威数据；管理变更请求 M1/M2 处置；负责通知投递 |

查询结果只是当时快照；提交预约、终审、报修和管理变更时，所属服务须重新判断状态。跨服务 HTTP 不在同一个数据库事务内，发起方按[接口契约](14_跨模块接口_V1.md)处理“处理中”、重复请求和失败恢复。课程要求的整室占座、报修下架及限制来源追溯均在相应 BP/AC 中验收。

实际 URL、字段、表结构、部署端口和运行拓扑尚未设计完成；PostgreSQL 实例数量待核实当前电脑资源。这些实现细节在接口细化与环境搭建时落到代码、迁移脚本及[运行文档](operations.md)，不在此凭空确定。
