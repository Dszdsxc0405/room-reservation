DeepSeek Harness 的 agent 开发规范不只在 `docs/`，还包括各层 `AGENTS.md`、`.agents/` 和自动检查脚本。中英译文、生成资料和历史文件使其文档数量很大，本项目不应按文件数量建目录。

## DeepSeek Harness：九类文档各管一件事

下表路径相对 DeepSeek Harness 仓库根目录；每类只概括一个主要职责。

| 类别 | 代表位置 | 一句话作用 |
|---|---|---|
| 常驻开发指令 | `AGENTS.md`、`docs/AGENTS.md`、其他子目录 `AGENTS.md` | 规定所有 agent 或特定目录内的常驻约束，并指向详细规则。 |
| 总体架构与运行流程 | `docs/architecture.md`、`docs/agent-lifecycle.md` | 说明系统如何组成，以及主要行为如何跨组件运转。 |
| 子系统与包契约 | `docs/subsystems/`、各包 `README.md` | 定义各组件负责的事实、类型、接口和使用限制。 |
| 设计决策记录 | `.agents/notes/` | 保存重要方案的理由、放弃的选项和实施状态。 |
| 代码评审与测试规则 | `docs/defensive-patterns/`、`docs/testing.md` | 列出必须防范的缺陷、测试证据和评审标准。 |
| 实操教程与专项工作流 | `docs/cookbook/`、`.agents/skills/` | 给重复出现的开发任务提供步骤和验证方法。 |
| 产品使用指南 | `docs/user/` | 教最终使用者和扩展开发者完成实际操作。 |
| 开发与文档治理 | `docs/development.md`、`docs/i18n/`、生成的参考目录 | 说明环境和日常开发流程，并检查文档、译文与代码是否同步。 |
| 变更与事故历史 | `docs/upgrade-guide/`、`docs/persistence-changes/`、`docs/postmortem/` | 保存升级、数据兼容和事故原因及处理证据。 |

核心做法是**一项事实有一个正文归属，其他文件链接它**；文档规则还要由评审和自动检查落实。

## 当前规范应优先落实的课程要求

完整任务书第 2～3 页要求 AI 生成的变更**经人工验收后提交**，合并请求经评审，代码冲突由人处理；还要求“先出方案再实现”、有意义的测试、需求追踪和持续记录工程伦理。现已将提交前人工验收及人工处理合并冲突写入根目录协作规范；自动检查、迁移、部署与回退须在环境搭建时用实际脚本和记录证明，不能只靠文档承诺。
