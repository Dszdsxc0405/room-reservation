# 工程伦理过程记录

> 课程要求在开发过程中持续思考工程伦理，而不是期末补写。以下是**待检查的风险**，不是已发生事件，也不新增业务需求；若需改变用户可见规则，先由需求负责人决定并更新 BP/AC。

| 待关注问题 | 现有依据与检查点 | 当前状态 |
|---|---|---|
| 学生预约、姓名与违约记录的隐私 | 学生只看本人记录；授权教室管理员和系统管理员按范围看详情；开发时验证服务端权限 | 规则已定，未实现/验证 |
| 未签到处置的公平性 | 只有真正超时未签到记违约；管理、整室或维修取消不记违约；检查边界时刻和取消原因 | 规则已定，未实现/验证 |
| 教室编码能否证明到场 | Web 输入预约教室当天编码；编码可能被转告他人，不能把它宣称为绝对的现场证明 | 风险待评估，不能擅改签到规则 |
| 管理变更对学生的影响 | 冲突预约取消并发站内消息；限制解除后不自动恢复，需检查提示是否清楚 | 规则已定，未实现/验证 |
| AI 生成代码的责任 | 先说明方案、测试真实行为、人工验收后提交；保留评审和 Git 记录 | 流程已写，尚无开发实践证据 |

## 过程记录方式

每遇到实际问题，简记“日期与阶段、影响对象、观察到的事实、选择及理由、验证证据、仍存疑问”；没有发生的事保持“待评估”。记录不含真实学生身份信息。组内记录供各成员写**个人**课程论文时引用各自参与的真实过程，论文不由本仓库代写或冒充个人经历。
