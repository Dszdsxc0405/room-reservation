## 5. V1 发布与变更规则

发布正式 V1 前：①审查现行 BP 的边界和影响系统结果的 Q，原 BP-04 查看用例按 BP-03 审查；②确认本次系统范围、US/AC 及明确不在范围内的功能；③保留已确认的 R-13～21 的来源、日期与未决边界。正式开发前，六人再对 M1/M2/M3/D、数据归属、关键契约、技术栈和验证分工作有记录的决策。未确定的业务结果不能伪称已确认，也不能由开发组自行补定。

开发期间如出现新的 BP 证据或业务决定，记录 `原因 → 影响的 R/Q/BP/CAP/US/AC → 契约/实现/测试 → 评审与版本`；只修订受影响行并保留旧结论。基线 V1 可按变更流程修订，但本项目当前不安排分批增量交付。
