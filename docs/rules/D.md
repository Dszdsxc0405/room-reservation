# D 公共层开发规则

> 状态：从[BP-03](../02_BP-03_空间与座位维护_V1.md)、[BP-05](../04_BP-05_系统配置与权限_V1.md)及[决策记录](../08_业务决策记录_V1.md)整理的开发参考，不新增业务决定。术语见[共享领域词典](../domain.md)；阶段名称不预设数据库枚举。

## 本模块负责的事实

D 修改教室和座位主数据、开放时间与时长上限、角色及教室授权、站内消息投递记录和操作审计；D 提供授权范围内的运营查询与统计。个人预约由 M1 修改，整室申请由 M2 修改，报修工单由 M3 修改。见[数据归属](../12_六人分工与数据归属_V1.md)。

## 状态与事件

| 对象 | 当前事实 | 事件 | 结果 | 依据 |
|---|---|---|---|---|
| 教室、座位 | 未登记 | 有权限的管理员登记并核对唯一编号 | 主数据可供查询；开放教室须配置至少一名获授权教室管理员，能否预约仍取决于开放、资格及其他限制 | BP-03 AC-11 |
| 座位 | 已登记 | 有权限的管理员修改插座标记 | BP-01 查询反映最新标记 | BP-03 AC-13 |
| 教室、座位 | 已登记 | 停用、恢复或注销，立即或未来生效 | 按生效时段改变可用性；注销后保留历史 | BP-03 AC-12 |
| 开放时间 | 已配置 | 有权限的管理员调整，立即或未来生效 | 新业务按对应时点配置判断；保存缩短计划时处置冲突安排 | BP-05 AC-36 |
| 关闭或缩短开放计划 | 已保存、尚未生效 | 有权限的管理员撤销计划 | 解除本计划造成的限制；此前取消的预约或申请不自动恢复 | BP-03 AC-12；BP-05 AC-36 |
| 预约时长上限 | 已配置 | 系统管理员调整个人上限 | 已生效的旧个人预约保留；新提交按当前上限判断 | BP-05 AC-15 |
| 整室时长上限 | 已配置 | 系统管理员调低整室上限 | 旧批准保留；待审申请按新上限重验，新提交按新上限判断 | BP-05 AC-15；BP-06 AC-17 |
| 管理员权限 | 已授权 | 系统管理员撤销角色或教室授权 | 新操作按当前权限判断；原审批人不能处理旧待办；撤销开放教室最后一名管理员授权前须先补人 | BP-05 AC-16 |

## 规则与不变量

| 规则 | 输入与条件 | 必须得到的结果 | 依据 |
|---|---|---|---|
| 主数据与归属 | 教室归属、教室/座位唯一编号、座位所属教室和插座标记 | D 是这些事实的修改方；注销后历史预约和管理记录仍按原权限可查 | BP-03 AC-11～13 |
| 资源管理范围 | 操作者角色与明确的教室授权 | 教室管理员只维护获授权教室及座位；系统管理员可管理全部；开放教室始终有至少一名获授权教室管理员 | BP-03 AC-11/12 |
| 开放时间归属 | 教室及开放时段 | 只在 BP-05 的配置管理中设置；系统管理员及该教室获授权管理员可修改 | BP-05 AC-36；决策记录 Q-20/21 |
| 预约上限 | 个人或整室单次时长配置 | 两种上限独立，初始分别为 4、8 小时；个人上限降低不追溯取消已生效旧预约，整室上限降低保留旧批准、待审按新上限重验 | BP-01 AC-02/03；BP-05 AC-15；BP-06 AC-17 |
| 管理关闭或缩短开放 | 立即或未来生效时间、受影响教室和时段 | 保存计划时取消生效后冲突的未来个人预约与整室批准、撤销待审整室申请并通知；生效前安排保留，立即生效时已签到正在使用的个人预约及正在使用的整室安排可到原定结束；撤销计划不自动恢复取消的安排，相关取消不记未签到违约 | BP-03 AC-12；BP-05 AC-36 |
| 单座位注销 | 被注销座位及其未来安排 | 取消该座位冲突的未来个人预约并通知；已签到正在使用的个人预约可到原定结束；整室批准和待审申请保留，告知该座位不可用 | BP-03 AC-12 |
| 角色与授权 | 系统管理员、教室管理员、当前授权 | 仅系统管理员可授撤管理员角色和教室授权，且不能给自己新增权限；撤销最后一名开放教室管理员前先补人，撤销后新操作按现有授权判断 | BP-05 AC-16 |
| 站内通知 | 业务模块提供收件人、内容与触发时点 | D 投递并记录结果；投递失败保留记录重试，不回滚已确认业务结果 | BP-02 AC-07～09/33；[接口](../14_跨模块接口_V1.md) |
| 管理查看范围 | 管理员角色、教室授权、所选教室和日期 | 仅获授权教室管理员或系统管理员可看相应学生姓名和单笔预约详情；注销后的历史仍按原权限查询 | BP-03 AC-14 |
| 运营统计 | M1 提供预约、签到及违约事实 | 预约量、取消数、签到量、未签到违约量和签到率均归属预约使用日；预约量含后续取消，取消数单列；签到率仅纳入需要签到且结果已确定的预约，管理/维修/审批取消不入分母，超时未签到计入 | BP-03 AC-14 |

签到率按“已签到笔数 ÷ 需要签到且结果已确定的预约笔数”计算；各统计项均按预约使用日归属。

## 跨模块依赖

| 对方 | D 使用或提供的事实 | 失败时的约定 |
|---|---|---|
| M1 | 提供主数据、开放配置和权限；管理关闭、缩短开放或座位注销时请求限制及取消，撤销计划时请求解除本来源；管理查看读取预约事实 | M1 未确认前管理计划保持“处理中”；统计不直接修改 M1 事实 |
| M2 | 管理关闭或缩短开放时请求撤销待审、取消未来批准；D 为其提供申请资格与当前审批权限 | M2 未确认前管理计划保持“处理中” |
| M3 | 为报修提供教室、座位和管理员授权；整室等业务查询报修状态由 M3 提供 | D 不直接修改工单或维修状态 |
| M1/M2/M3 | 接收业务通知与审计请求 | 通知失败单独记录并重试，不改变已确认的业务结果 |

跨模块写入使用唯一操作编号并按[接口](../14_跨模块接口_V1.md)重试；D 不直接修改 M1、M2、M3 的业务记录。
