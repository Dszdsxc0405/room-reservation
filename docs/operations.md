## 当前可运行部分

仓库根目录的 Maven Wrapper 可构建单个 Spring Boot 后端；M1/M2/M3/D 是内部业务模块。`web/` 有 Vue 开发服务器和生产构建。当前容器中的开发库配置在仓库外的 `/opt/room-reservation/secrets/application-rr-dev.properties`，本地测试库配置在同目录的 `application-rr-local-test.properties`；它们只用于本容器，团队成员参照[配置示例](../config/application-db.example.properties)创建自己的私有配置。后端默认监听本机 18080（当前容器的 8080 已被其他进程占用），Web 开发服务器由 Vite 报告访问地址；实际启动命令见[仓库 README](../README.md)。

已执行 `./mvnw -B -ntp verify`、`npm ci`、`npm run type-check`、`npm run lint`、`npm run build`。单个后端在开发库配置下的 `/actuator/health` 通过 HTTP 返回 `UP`，Web 首页可通过 Vite 访问。当前无自动测试、业务 API、内部模块调用和迁移脚本；健康检查不构成这些能力的验证。

| 环节 | 计划中的做法 | 需保存的完成证据 |

三套环境计划运行在 Debian 12 机器上：开发使用原生 PostgreSQL 专用库，本地与 CI 测试使用各自的测试库，部署测试与生产演示分别使用独立 PostgreSQL 容器和持久卷。能否同时运行待资源核实，环境间不得共用业务数据库。具体端口、密钥保管位置、Runner 配置和恢复结果须以实际环境验证后填入搭建记录；不得把计划写成已完成。迁移不靠人工改库，部署镜像应能追到 Git 提交。个人凭据和生产秘密不进入仓库。
