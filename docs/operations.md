# 环境、数据与发布

> 本文是运行总览；具体执行顺序与检查方法见[搭建手册](环境与流水线搭建.md)，实际结果使用[搭建记录模板](环境与流水线搭建记录_模板.md)。技术选择见[技术方案](13_技术方案_V1.md)，阶段顺序见[后续步骤](15_需求分析后续步骤.md)。目前仅有本地 Git 仓库，未搭建环境、流水线或数据库。

| 环节 | 计划中的做法 | 需保存的完成证据 |
|---|---|---|
| 环境 | 在 Debian 12 机器核实资源；开发和本地测试原生运行，测试与生产演示部署使用独立 Docker 镜像和数据库卷 | 环境配置、资源检查和启动结果 |
| 构建与检查 | 私有 GitHub 仓库的提交和合并请求触发构建、测试；失败阻断后续阶段 | 对应提交、构建日志及测试结果 |
| 数据演进 | 所属模块提交版本化 Flyway 迁移；种子数据脚本幂等且与业务数据分离 | 从空库重放至最新版本、重复执行种子脚本的结果 |
| 测试部署 | 流水线自动部署本组全部模块；使用部署窗口或等效锁，避免部署中联调误报 | 部署版本、时间、模块清单及联调结果 |
| 生产发布 | 按 tag 人工审批发布，协调组内模块顺序，并可回退 | 审批记录、运行版本、发布变更与回退演练 |

三套环境计划运行在 Debian 12 机器上：开发使用原生 PostgreSQL 专用库，本地与 CI 测试使用各自的测试库，部署测试与生产演示分别使用独立 PostgreSQL 容器和持久卷。能否同时运行待资源核实，环境间不得共用业务数据库。具体端口、密钥保管位置、Runner 配置和恢复结果须以实际环境验证后填入搭建记录；不得把计划写成已完成。迁移不靠人工改库，部署镜像应能追到 Git 提交。个人凭据和生产秘密不进入仓库。
