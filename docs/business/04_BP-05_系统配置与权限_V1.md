# BP-05 系统配置与权限 V1

> 状态：主线及 AC-15/16/36 已获认可；Q-05/17/20/21 核心规则已决定。依据：[课程任务书](Pj-任务书.pdf)附件 1，第 5 页及 D 公共层说明。

## 1. 边界与主线

起点为有管理权限的人员希望调整系统参数、教室开放时间、角色或权限；终点为配置保存并按约定时点生效，关联业务流程依新的规则判断。主线：查看当前配置 → 调整个人或整室预约时长上限、开放时间或权限配置 → 核验管理权限和参数合法性 → 保存与追溯 → 受影响的 BP 使用新配置。整室上限独立配置，初始 8 小时（Q-22）。系统管理员可管理全部配置；教室管理员可配置其获授权教室的开放时间（Q-20）。

分支：改变预约上限、角色权限或教室开放时间；改变现有学生或管理员的权限；配置与已生效预约或在途审批冲突。个人时长上限调整保留旧预约，新提交按新上限；整室上限下调保留旧批准，待审申请按新上限重验，不符合者不得继续获批。审批权限撤销后，原审批人不能继续处理待办，由当前有权限者处理（Q-05）。仅系统管理员可授予或撤销管理员角色及教室授权，且不能给自己新增权限（Q-20）；开放教室须始终有至少一名获授权教室管理员，撤销最后一人授权前须先补人。教室与座位主数据、可用性由 BP-03 维护；开放时间只由本 BP 配置（Q-21）。开放时间变更可立即或在指定未来时间生效；保存关闭或缩短开放时间计划时，生效前安排保留，生效后冲突的未来个人预约和已获批整室安排立即取消，待审整室申请立即撤销，均发站内消息且不记未签到违约；立即生效时当前已签到使用或正在使用的整室安排可到原定结束；已开始但尚未签到的个人预约保留到原签到截止时点，期间可按原规则签到并使用到原定结束，逾期未签到按通常规则记违约。撤销计划不自动恢复此前取消的安排，可重新预约或申请。

## 2. 事实、能力与故事

配置项、角色、权限、用户角色关系、变更人和生效时间是业务事实。R-10：系统管理员可管理配置、角色及权限，并可设定可用自习室/开放时间。R-01 的单次最长时长“可调”在本流程落地。RBAC、空间主数据和操作审计属于任务书 D 的范围线索，但具体 D 归属由六人决定。

|---|---|---|
| CAP-09 管理配置及生效范围 | UC-11 系统管理员调整预约规则及开放时间 | US-11 调整个人/整室预约时长上限或教室开放时间 |
| CAP-10 管理角色权限并审计变更 | UC-12 系统管理员配置角色权限 | US-12 维护角色与其可操作范围 |

| AC | 前提 / 操作 / 结果 |
|---|---|
| AC-15 | 系统管理员将个人单次时长上限改为 3 小时并使其生效；已生效的 4 小时旧预约保留，随后学生提交 4 小时的新预约被拒绝、3 小时在其他条件满足时可成功。若整室上限从 8 小时降为 4 小时，旧的 8 小时批准保留；待审的 8 小时申请按新上限重验后不得获批，新提交的 8 小时申请被拒绝（R-01/R-10/Q-05） |
| AC-16 | 系统管理员撤销某审批人的权限后，该人不能继续处理已收到但未完成的申请，改由当前有权限者处理；若其是开放教室最后一名管理员，须先补人才能撤销授权。教室管理员不能授予管理员角色或教室授权，系统管理员不能给自己新增权限；其他新的管理操作按当前授权判断（R-10/Q-05/20） |
| AC-36 | 周四由系统管理员或获授权教室管理员保存周五起缩短开放时间的计划；变更前时段的预约保留，变更后冲突的个人座位预约和已获批整室安排立即取消、待审整室申请立即撤销，均发站内消息且不记未签到违约；受影响时段不能再被新预约选中。若变更立即生效，已签到正在使用的个人预约及正在使用的整室安排可到原定结束；若 10:05 缩短开放时间时某笔 10:00 开始的个人预约尚未签到，M1 在 10:15:00（含）前受理且输入预约教室**预约使用日**有效编码仍可签到，签到后使用到原定结束；10:15:01 起仍未签到则按通常规则取消并记一次违约；撤销未来计划不自动恢复此前取消的安排（Q-04/15/17/20/21） |
