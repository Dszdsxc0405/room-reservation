# BP-07 故障上报、维修与验收：分析候选 V0

> 状态：主线及 AC-20～23 已认可；教室与座位分别报修，Q-02/12/25～28 已决定。依据：[课程任务书](Pj-任务书.pdf)第 1–2 页及用户 2026-11-05 的资源粒度决定。

## 1. 边界与主线

起点为学生或管理员上报教室或座位故障；终点为工单完工、验收与评价，相关维修限制解除。主线：上报并标明教室/座位 → 教室管理员派单 → 维修员处理并记录进度 → 进入“维修中”时按资源范围下架 → 满 72 小时未完工则通知系统管理员、原维修员继续负责 → 提交完工 → 教室管理员验收通过后自动解除该工单限制 → 原报修人评价。教室工单下架全室座位；座位工单只下架该座位。报修或派单时尚不下架（Q-25/26/28）。

| 分支/先后顺序 | 已知结果或 Q |
|---|---|
| 报修但尚未进入维修中 | 不下架；进入“维修中”才施加限制（Q-25） |
| 教室工单进入维修中 | 下架全室座位；取消冲突的未来个人预约并通知、不记违约；撤销重叠待审整室申请、取消已获批整室安排并通知申请人（Q-02/24） |
| 座位工单进入维修中 | 只下架该座位；取消该座位冲突的未来个人预约并通知、不记违约；整室申请可提交但提示该座位不可用，已获批整室安排保留 |
| 维修超时 | 自进入“维修中”起满 72 小时未提交完工，通知系统管理员并留记录；原维修员继续负责（Q-26） |
| 完工但验收不通过 | 退回“维修中”，资源继续下架，由教室管理员重新派工（Q-27） |
| 报修人主动取消 | 仅进入“维修中”前可取消；尚未下架的资源不受影响（Q-27） |
| 同一资源已有未结束工单 | 不允许重复报修；教室和座位分别按各自资源判断（Q-28） |
| 验收通过且另有维修工单或整室占用 | 只解除本工单限制；仍受其他限制时不可约（R-17）；多工单细节 Q-28 |

## 2. 事实、事件与规则

故障描述、故障资源类型（教室/座位）、工单、派工、处理记录、状态时点、验收与评价是业务事实。R-12：M3 支持上报、派单、维修中、超时升级、完工验收与评价；R-04：教室工单维修中下架全室座位，座位工单维修中只下架该座位；验收通过后自动解除本工单影响；R-05：写入来源可追溯。维修中时取消影响范围内的未来个人预约并通知、不记违约（Q-02/15）；教室维修还按 Q-24 撤销/取消整室申请。

任务书明确要求教室维修中全室下架；用户进一步明确座位可独立报修，座位工单只影响该座位。验收后的“恢复”只解除本工单来源，仍须检查其他限制；不能覆盖 BP-06 的整室占用。
