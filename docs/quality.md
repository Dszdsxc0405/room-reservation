# 质量与验证约定

> 当前只有已确认的 BP/AC，没有系统代码、测试结果或 CI。验收结果以[需求与验收追踪](requirements.md)记录的真实证据为准；协作评审和提交顺序见[CONTRIBUTING](../CONTRIBUTING.md)。

| 验证层次 | 重点行为 | 完成证据 |
|---|---|---|
| 规则和数据约束 | 整点/跨日/提前三天、权限、重叠预约、状态转换 | 自动测试及数据库约束的实际结果 |
| 模块接口 | 每个服务的成功、拒绝、重复请求和错误响应 | HTTP 接口测试记录 |
| 跨模块联调 | 整室终审占座、报修提交下架、管理计划取消、来源解除、通知失败 | 四服务真实网络调用的结果 |
| Web 与人工验收 | 各角色操作、可见范围、提示与 BP/AC 结果 | 浏览器测试和逐项人工验收记录 |
| 并发与容量 | 热点座位至多一笔成功；分散预约的排队、锁等待和资源占用 | 压测报告；1000 虚拟用户只是示例，不是已承诺指标 |

AI 生成代码需重点检查：是否凭空补业务规则、用常量断言或 mock 掉被测逻辑、遗漏服务端 RBAC、只在查询时检查冲突、跨模块直接改表、在超时重试时重复取消或通知。评审以 BP/AC、模块规则和接口契约为依据，验证实际行为，不以代码自述为证据。

至少选一条关键自动测试，在独立任务分支**故意破坏被测行为**（如移除预约冲突保护），确认测试失败，再恢复实现并确认测试通过；保存两次结果。尚未执行时不得写“已验证”。构建、类型检查、测试和文档检查的真实命令待环境搭建后补入[运行文档](operations.md)，并设置提交/合并请求的自动门禁。
