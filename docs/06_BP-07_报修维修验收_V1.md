# BP-07 故障上报、维修与验收 V1

> 状态：主线及 AC-20～23 已认可；教室与座位分别报修，Q-02/12/25～28 已决定。依据：[课程任务书](Pj-任务书.pdf)第 1–2 页及用户 2026-11-05 的资源粒度决定。

## 1. 边界与主线

起点为学生或管理员上报教室或座位故障；终点为工单完工、验收与评价，相关维修限制解除。主线：上报并标明教室/座位，当即停止受影响资源的新约并取消未来预约或整室安排 → 教室管理员派单 → 正在使用的安排结束后，维修员进入“维修中”并记录进度 → 满 72 小时未完工则通知系统管理员、原维修员继续负责 → 提交完工 → 教室管理员验收通过后解除该工单限制 → 原报修人评价。教室工单影响全室座位及整室安排；座位工单只影响该座位。报修时已开始但尚未签到、尚未构成超时的个人预约立即取消且不记违约；若此前已构成超时未签到，即使任务延迟也先按超时处置并记违约，再处理报修。已签到正在使用的座位预约或整室安排可用到结束（Q-02/24/25/26；2026-11-20 延迟处置决定）。

| 分支/先后顺序 | 已知结果或 Q |
|---|---|
| 报修提交时 | 教室工单立即限制全室座位和新整室申请、座位工单立即限制该座位的新约；取消影响范围内未来个人预约，教室工单同时取消未来整室批准、撤销待审申请，均发站内消息且不记违约；已签到正在使用的预约或整室安排可用到结束（Q-02/24/25） |
| 个人预约已开始但尚未签到，报修覆盖其座位，且尚在原签到窗口内 | 报修提交时立即取消该预约并通知，不记未签到违约；学生不能再凭这笔预约签到 |
| 个人预约已在截止后一秒构成未签到超时，任务延迟，随后报修覆盖其座位 | 先按原截止时点补做超时取消、一次违约和通知，再施加报修限制；报修不能覆盖已构成的违约结果 |
| 教室报修提交时 | 撤销重叠的未来待审整室申请、取消未来已获批整室安排并发站内消息；正在使用的整室安排可用到结束（Q-24） |
| 座位工单进入维修中 | 该座位限制持续；整室申请可提交但提示该座位不可用，已获批整室安排保留 |
| 维修超时 | 自进入“维修中”起满 72 小时未提交完工，通知系统管理员并留记录；原维修员继续负责（Q-26） |
| 完工但验收不通过 | 退回“维修中”，资源继续下架，由教室管理员重新派工（Q-27） |
| 报修人主动取消 | 仅进入“维修中”前可取消；解除该工单的预约限制，已因此取消的个人预约和整室批准/待审申请均不自动恢复，可重新预约或申请（Q-27） |
| 同一资源已有未结束工单 | 不允许重复报修；教室和座位分别按各自资源判断（Q-28） |
| 验收通过且另有维修工单或整室占用 | 只解除本工单限制；仍受其他限制时不可约（R-17）；多工单细节 Q-28 |

## 2. 事实、事件与规则

故障描述、故障资源类型（教室/座位）、工单、派工、处理记录、状态时点、验收与评价是业务事实。R-12：M3 支持上报、派单、维修中、超时升级、完工验收与评价；R-04：任务书规定教室维修中全室下架、座位维修中只下架该座位，验收后解除本工单影响；用户进一步决定报修提交时就限制新约并取消未来个人预约和整室安排，正在使用的安排可用到结束（Q-02/24/25）；R-05：写入来源可追溯。

任务书明确要求教室维修中全室下架；用户进一步明确座位可独立报修，座位工单只影响该座位。验收后的“恢复”只解除本工单来源，仍须检查其他限制；不能覆盖 BP-06 的整室占用。
